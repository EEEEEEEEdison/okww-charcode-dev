# 角色语义卡

一张卡记录一个角色在某个共鸣链下的知识。
文件名为 `<类名>_C<共鸣链>.md`，例如 `Cantarella_C0.md`。
内容包括机制、按法、画面识别、实测时长和代码经验。
条目只写结论，不带来源和适用条件。

## 读取与适用条件

- 轴解析读取作者共鸣链对应的卡。
- 双方共鸣链不同时，按 [step1.md §2](../../guides/step1.md) 核对差异。
- 代码实现、实测迭代及局部修改先读涉及角色的卡。
- 没有对应卡时，登记缺项，不得把 C0 条目直接视为适用。
- 卡里的时长和识别阈值，必须在当前游戏版本、框架与录屏条件下核对后再用。
- 用户确认意图与实测验证机制必须分别记录。
- 来源不足时，不得把已有条目写成当前任务的实测结论。

## 使用边界

角色代码开发任务只读取安装包中的知识和规则。
执行这类任务时，不得改写本 Skill 安装目录。
队伍代码、试验结果和新证据写入用户工作区。

新证据与卡片冲突时，在本案中记录来源、适用条件和影响。
缺项按 [evidence.md §4](../../guides/evidence.md) 处理。
会改变行为的未知必须先满足对应阶段的通过条件。
普通开发流程不得改写卡片，不得发起补卡确认。
实测得到可入卡的发现时，只能按 [知识提议 Skill](../../skills/proposal/SKILL.md) 起草提议，由用户决定是否反馈给维护者。
