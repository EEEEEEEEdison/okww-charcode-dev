# 角色语义卡

一张卡记录一个角色在某个共鸣链下的知识，目的只有一个：帮助写出在游戏里跑得通、bug 少的代码。内容可以是游戏机制、按法、画面识别、实测时长，也可以是开发中验证过的代码经验。按共鸣链分卡，是因为不同共鸣链下技能表现不同；卡的内容不只是共鸣链效果。

## 规则

- **粒度**：一个角色的一个共鸣链一张卡，文件名为 `<类名>_C<共鸣链>.md`，例如 `Cantarella_C0.md`。
- **入卡标准**：以下两条都满足才入卡。
  - 换一个轴也成立。只和某个轴有关的，记在案例目录里。
  - 对写出能跑通、bug 少的代码有用：或者帮助判断按法和出招顺序，或者直接决定代码怎么写。纯养成信息（共效、伤害倍率等）不再新增。
- **分流**：不是只对这个角色成立的知识，不进卡：

  | 适用范围 | 写进 |
  |---|---|
  | 只对这个角色成立 | 本卡 |
  | 所有角色通用的写法 | [../../rules.md](../../rules.md) 的对应分组 |
  | 和角色无关的游戏常识 | [../basics.md](../basics.md) |
  | 只和这个轴有关 | 案例目录 `cases/<队名>/` |

- **候选来源**只有以下五种，不上网查 wiki：
  - 视频简介和评论；
  - 视频画面推断；
  - 用户提供的攻略；
  - 用户的回答；
  - 实测：ok-ww 跑生成代码时的日志和录屏。
- **写法**：技能用描述性名称（如“强化普攻”“终结技能”），不写轴记号；记号的常见写法放在 basics.md N-2。
- **入卡前先经用户确认**：只有用户确认过的条目才能写进卡里，确认方式见下面的「补卡机制」。
- **用卡**：
  - 步骤 1 用作者共鸣链的卡来理解视频。作者和用户共鸣链不同时，受影响的步骤要问用户（step1.md §2）。
  - 步骤 2 生成代码、实测迭代，以及直接写或改某个角色的代码时，先读这个角色的卡。

## 补卡机制

### 触发点

以下时机，AI 主动检查有没有该补进卡里的内容，不需要用户提醒：

1. 步骤 1 集中提问结束后（step1.md §8）：看用户的回答。
2. 每轮实测迭代分析完之后（iterate.md §5）：看用户对实测结果的反馈、日志和录屏量出的结论、上一轮改代码的根因和改法。
3. 直接写或改代码时（SKILL.md 用法 B）：用户纠正了某个角色的出招、时长或写法。
4. 新证据和卡里已有的条目冲突时。

### 起草

- 先读这个角色的卡，找同一主题的旧条目：能改就改，能合并就合并；被新证据推翻的直接改掉或删掉，不保留“已废弃”标注。
- 按入卡标准和分流表决定写到哪里，再按模板放进对应的节。
- 「代码经验」只写实测验证过的写法：改动后的版本经实测确认有效，才入卡。还没实测的改法不入卡。

### 批量确认

- 每轮结束时（一次集中提问结束，或一轮迭代分析完），用 AskUserQuestion 把起草的条目一次列出：
  - 用多选题，每个选项是一条：label 写“<角色> <节名>：<要点>”，description 写完整条目和来源；
  - 每题最多 4 条，超过就分成几题，每次调用最多 4 题；
  - 某题只剩一条时，改用单选题，选项为“写入”和“不写入”。
- 用户勾选的才写进去，并在条目上写确认日期。没勾选的不写。
- 分流到 rules.md 和 basics.md 的条目，同样走这个确认。

## 卡片模板

```markdown
# <中文名>（<类名>）<共鸣链> 链

## 技能与按法
- E：……（来源：<视频简介 BVxxxx / 画面推断 BVxxxx@12.3s / 用户攻略 / 用户回答 / 实测 <队名> harness-v<N> 录屏 test_xxxx@12.3s>；用户确认 <日期>）

## 状态与识别
- 图标、HUD 的变化，以及怎样从画面上判断

## 时序
- 出招顺序、动作之间的间隔和时长

## 代码经验
- 验证过的写法：采用的判据（区域、阈值、用到的函数）、按住多久、等待和时限、踩过的坑。写明出处，例如 `ok-ww-char/<队名>/harness-v<N>/<类名>.py` 的 `<函数名>`

## 补充说明（可选）
- 不直接决定按键、但有助于理解出招意图的机制，例如某个 buff 决定了为什么要先放某个技能
```

- 每条都要写明来源和用户确认日期。
- 实测得到的数值和写法，还要写两项：
  - **实测状态**：多次一致（写明次数），或者单次观察；
  - **适用条件**：游戏版本、ok-ww 基线、录屏分辨率。游戏更新后，靠这一项判断数值是否需要重测。
- 已有的卡不批量重排。以后补到哪张卡，再把那张卡整理成这个结构。
