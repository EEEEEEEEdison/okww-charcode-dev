# 角色帧数据

帧数据记录角色动作的帧数、中断优先级、能量回收和输入缓存。
数据来自维护者提供的《鸣潮数据汇总》，是可信资料。
每个文件开头写明数据版本。
[_index.md](_index.md) 列出数据汇总的版本、校验值，以及名称与文件的对应关系。

## 文件

- 一个文件对应框架里的一个角色类，文件名为类名，例如 `Chisa.md`。
- 漂泊者按属性分为 4 个文件：`SpectroRover.md`、`HavocRover.md`、`AeroRover.md`、`ElectroRover.md`。男女漂泊者写在同一个文件。
<!-- stc-disable-next-line -->
- 一个角色有多个形态时，每个形态一节，例如 `Hsin.md` 分为应世心和照世心两节。
- `_common.md` 收录闪避等通用动作，按体型分为通用-大、通用-中、通用-中小、通用-小。
- 每节标题写数据汇总中的名称、工作表和行号。
- 文件末尾的“输入缓存（秒）”一节写该角色的指令缓存。

## 列含义

表中时间的单位是帧（F），60 F 为 1 秒。
派生帧、派生持续帧和动作结束帧在括号里附秒数。
整块为空的列不显示。

| 列 | 含义 |
|---|---|
| ID | 技能编号。ID 为空的行沿用上一行的 ID，属于同一技能 |
| 动作 | 动作或判定的代称，见下方“动作名称” |
| 备注 | 动作过程的功能说明，例如“第 48F 前不响应输入” |
| 发生帧 | 判定生成的时间点。为空表示该判定由效果触发，与角色动作无直接关系 |
| 持续帧 | 判定生效后的持续时长。-1 表示动作不停，判定就一直持续。为空表示没有判定 |
| 无敌 | 通用无敌的“启动帧+持续帧”。通用无敌期间仍会被命中，但不影响任何状态计量表。备注写“不会被命中”时为真无敌 |
| 派生帧 | 开始能衔接下一个技能的时间点。顿帧会推迟派生帧 |
| 派生持续帧 | 能衔接下一个技能的时长 |
| 动作结束帧 | 角色进入完全可控状态的时间点 |
| 中断优先级 | 技能的取消等级。动作过程中改变时写成 `a,b,c` |
| 优先级改变 | 中断优先级改变的时间点，与中断优先级的各个值依次对应 |
| 位置状态 | 地面、空中、地转空、空转地等 |
| 时停 | 时停或全局时停的类型与持续帧 |
| 大招回收 | 获得的共鸣能量。一行有多次判定时，值是各次判定与动作自带能量之和 |
| 协奏回收 | 获得的协奏能量，算法同大招回收 |
| 核心回收 | 获得的核心能量。多个值用 `/` 分隔 |

### 动作名称

- A：普通攻击。A1-2 表示第 1 下普攻的第 2 段判定。
- 重击：长按普通攻击或蓄力攻击。
- 空中普攻：滞空攻击或下落攻击。
- E：共鸣技能。E4-1 表示第 4 套共鸣技能的第 1 段判定。
- QTE：变奏技能，即入场技能。
- 大招：共鸣解放。大招-前置是共鸣解放的镜头特写阶段。
- 极限闪避：闪避期间受到攻击时自动触发的动作。
- 闪避反击：极限闪避后短按普通攻击触发的技能。
- 同一角色有两条同名动作时，表示该动作在不同条件下的数据，按备注区分。

## 衔接与离场

### 中断优先级

中断优先级越大，能取消的技能越多。
派生帧之后，能衔接中断优先级不高于当前值的技能。
中断优先级的常见取值：

| 值 | 动作 |
|---|---|
| 0 | 延奏、动作取消前置 |
| 1 | 技能衔接前置 |
| 2～4 | 普攻 |
| 4～10 | 共鸣技能 |
| 6 | 地面闪避 |
| 7 | 空中闪避 |
| 8 | 地面极限闪避、闪避反击 |
| 9 | 闪避反击，以及个别角色的核心回路 |
| 10 | 共鸣解放 |
| 11 | 变奏技能 |

备注里的 3 种限制：

- 不响应输入：通常是中断优先级为 10 或以上，按键没有反应。
- 不能闪避：通常是地面时中断优先级为 6 或以上，空中时为 7 或以上。
- 不能切人：动作自带的特性，与中断优先级无关。

### 切人离场

战斗中切人后，被切走的角色可能继续留在场上，最多再停留 0.32 秒（19 F）。
停留期间，角色身上有刷新光效。

- 在动作结束帧前切人：被切走的角色继续执行动作，到动作结束帧 + 0.32 秒离场。
- 派生持续帧结束时，游戏做一次离场判断：角色在场且在后台时，到派生帧 + 派生持续帧 + 0.32 秒离场。
- 一个动作通过上述一种方式触发离场判断后，另一种不再触发。

## 输入缓存

“指令缓存”三个数依次是按下、抬起、长按的缓存秒数，0 表示没有缓存。
“长按触发”是按住多少秒算长按。

通用规则：

- 技能状态没有变化时，缓存时间内的输入能触发对应技能。
- 改变技能状态或重复输入，会清除或覆盖缓存。
- 同一按键有多个指令缓存时，触发其中一个就执行对应技能，并清除该按键的全部缓存。
- 角色进入后台时，输入缓存清空。

## 使用规则

- 数据版本与当前游戏版本一致时，帧数据可直接作为动作帧数的证据，不必实测验证。
- 当前游戏版本晚于数据版本时，改动过的技能可能不符。帧数据与录屏或实测冲突时，按 [evidence.md §3](../../guides/evidence.md) 保留冲突双方。
- 角色或形态没有帧数据时，按 [evidence.md §4](../../guides/evidence.md) 登记缺项。
- 比较实测耗时与帧数时，必须扣除顿帧、时停、切人过渡和框架开销。原因：表中帧数不含这些时间，实测耗时包含。
- 发生帧是判定生成的时刻，与 HUD 变化的时刻不一定相同。用帧数据推算读屏判据的时机时，必须先实测两者的差。
- 帧数据只说明游戏机制，不说明轴作者的操作意图。按法和意图仍按轴解析阶段确认。
- 普通开发流程不得改写帧数据文件。
