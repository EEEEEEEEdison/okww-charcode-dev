# 步骤 1：对照文字轴与视频，产出时序数据

输出是本案的 `cases/<队名>/harness-v<N>/timeline.json`，格式见 [timeline.md](timeline.md)。常识见 [../knowledge/basics.md](../knowledge/basics.md)。

脚本都当场写，用 ok-ww 自带的 Python 跑（带 `-I -B`），放在媒体目录或 scratchpad 里。

## 1 收集素材

**B 站链接**：只用公开接口，不登录，不带 cookie。请求头带普通浏览器的 User-Agent 和 `Referer: https://www.bilibili.com/`。

1. `https://api.bilibili.com/x/web-interface/view?bvid=<BV号>`：取标题、简介 `desc`、`aid`、`pages[].cid`、作者 `owner.mid`。
2. `https://api.bilibili.com/x/v2/reply?type=1&oid=<aid>&sort=2&pn=1&ps=20`：取置顶评论 `data.upper.top` 和热门评论 `data.replies`。
3. `https://api.bilibili.com/x/player/playurl?bvid=<BV号>&cid=<cid>&qn=80&fnval=16`：从 `data.dash.video[]` 里挑分辨率最高的流，同分辨率优先 `avc1` 编码，用它的 `baseUrl` 下载。只要视频流，不要音频。
   - 不登录一般只能拿到 480p。需要更清晰的，请用户提供本地文件。

把简介和评论整理成媒体目录里的 `info.md`，把视频保存为 `video.m4s`。

**本地文件**：直接使用。

**读视频**：`cv2.VideoCapture` 可以直接打开 `.m4s` 和 `.mp4`。先读出帧率、帧数、分辨率，记进 `timeline.json` 的 `sources.video`。

## 2 确认文字轴（关口 G1）

1. **候选来源**：用户粘贴的、视频画面里的（轴表常在左上角，字幕在底部）、简介、置顶或热门评论。
2. **读画面里的轴表**：截出轴表区域，放大 2 倍再读。注意颜色等标记，例如红字。
3. **作者的记号说明**：在简介里找"按键说明"一类的段落。找不到，或者遇到没见过的记号，按 basics.md N-1 去问。
4. **多套轴**：视频里有多套轴时（例如"30 秒轴 / 25 秒进阶轴"），问用户翻译哪一套。
5. **角色**：把轴里的角色简称（如"坎""嘉""弗"）对应到类名。对不上或有歧义就问。
6. **共鸣链**：先从视频和简介里找作者每个角色的共鸣链，找不到就问；同时问用户自己的共鸣链。两者不同时，受影响的步骤要列进问题清单。
7. **单独提问**：把候选文字轴原文、来源、作者记号说明、角色对应、共鸣链，作为第一个问题单独请用户确认。确认之前不进入第 3 节。

## 3 拆分记号

- 每一行拆成"角色 + 记号序列"。记号按 basics.md N-2 的词典和作者说明来认，不认识的进问题清单（类型 `notation`）。
- 连续几行是同一个角色时，可能是同一次上场分成了几行，也可能是两次上场，要以视频里的切人为准。视频看不出来就进问题清单。
- 多个连续的 A 记成一个普攻段，带上段数。

## 4 HUD 时间线

- 截取底部技能栏和回路条区域，按时间排成网格图，每格标上时刻，然后逐张查看。
  - 768×480 的视频里，这块区域大约是 x 285–745、y 418–470，放大 1.5 倍。其他分辨率按比例换算。
  - 先每 0.5 秒取一格粗扫，定位事件；再在关键区间每 0.1 秒取一格细扫。
- 要找的事件：
  - **切人**：技能栏的图标整组换掉；
  - **放 E/Q/R**：图标上开始出现冷却数字；
  - **大招动画**：HUD 消失的区间。
- 多段或强化的 E/R 放完不一定进入冷却（basics.md K-2、H-2）。这类情况要结合语义卡和动作画面来判断。

## 5 对齐

- 轴的每一行对应两次切人之间的一段，也就是一个节点。行数或顺序和视频对不上时，进问题清单（类型 `conflict`）。
- 视频里的事件和轴上的记号逐一对应：
  - E/Q/R 对应冷却数字出现的时刻；
  - R 还要对应大招动画；
  - ↓ 对应切人的时刻。
- 每个结论都标一个证据等级：

  | 等级 | 依据 |
  |---|---|
  | A | 画面上的按键显示 |
  | B | HUD 变化（冷却、图标、切人） |
  | C | 角色动作画面 |
  | D | 只能按时间推断 |

- 文字轴和视频不一致时，默认以视频为准，但视频证据必须是 A 或 B 级。只有 C/D 级证据时，进问题清单（类型 `conflict`）。

## 6 其余记号

A、Z、闪、跳，以及单击还是长按、按住多久，按以下顺序处理：

1. 查语义卡里已确认的条目，见 [../knowledge/cards/](../knowledge/cards/README.md)；要用作者共鸣链的那张卡。
2. 卡里没有，就看动作画面去推断，证据记为 C 或 D 级。
3. C/D 级的结论一律进问题清单（类型 `low_confidence`），让用户确认。

普攻段数、单击还是长按、按住时长目前是待专题项（basics.md H-3）。在专题出结论之前：
- 普攻段的时长按视频量出的起止时刻来记；
- 段数照抄文字轴。

## 7 多遍印证

视频里同一套循环出现多遍时，逐个节点比较各遍的时长和事件时刻：
- 某一步的时间在各遍之间基本一致，就记为"固定时长"；
- 波动大的，记为"满足条件才触发"，在 note 里写明猜测的条件，并进问题清单。

## 8 问题清单与集中提问

- 第 3–7 节全部做完后，把问题清单一次问完：
  - 用选择题，每题只问一个点，每次调用最多 4 题；
  - 附上截图路径（截图存在媒体目录 `frames/` 下）和视频时刻；
  - 有推荐答案的，把它放在第一个选项，并标上推荐。
- 用户的回答写进 `timeline.json`：对应 issue 的 `answer` 和 `status`，相关步骤的 `decided_by: "user"`。
- 回答如果是**角色本身的结论**（换一个轴也成立），先问用户"是否存入语义卡"，同意才写进去，格式见 cards/README.md。只和这一个轴有关的回答不存卡。
- 回答又引出新问题时，再问一轮，直到问题清单清空。然后进入关口 G2（timeline.md §3）。
