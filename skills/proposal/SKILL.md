# 知识提议

## 输入

本案 `notes.md`、`timeline.json.issues`、当前语义卡，以及本轮实测结论。

## 执行

1. 读取 [knowledge-maintenance.md §2–3](../../maintainer/knowledge-maintenance.md) 的入卡条件和条目写法。
2. 从本案挑出候选。候选必须满足入卡条件，并有可定位的证据。
3. 没有候选时，说明原因并结束，不生成文件，不提问。
4. 按 [提议模板](../../templates/knowledge-proposal.md) 逐条填写。原文照抄当前卡片，版本号取 [VERSION](../../VERSION)。
5. 脱敏：本机路径改为 `<工作区>`、`<ok-ww>` 等占位，删除用户名、账号、邮箱和令牌。视频只写链接和时刻。
6. 写入 `<工作区>/<队名>/proposals/<YYYYMMDD>-<短名>.md`，不得写入本 Skill 安装目录。
7. 用 [submit_proposal.py](../../scripts/submit_proposal.py) 检查，未通过时按输出改正：

   ```text
   <ok-ww python.exe> -I -B <本仓库>/scripts/submit_proposal.py <提议 .md> --dry-run
   ```

8. 给出提议全文，用宿主的结构化提问工具问一次。题干写明条数、反馈后公开在 GitHub Issue、同意按 MIT 许可收录。选项按第 7 步输出的 `gh:` 行和工作区根目录的 `okwwcharcode.local.md` 确定：
   - `gh: 已登录`，或本地配置记有 `gh 引导：不再推荐`：选项为“反馈”“用邮件反馈”“不反馈”。
   - 其他情况：选项为“安装 gh 后反馈”“用浏览器反馈”“用邮件反馈”“不反馈”。`gh: 未登录` 时，第一项改为“登录 gh 后反馈”。题干加上下面这段；`gh: 未登录` 时删掉安装那句：

     > 安装 GitHub CLI（gh）并登录后，以后每次反馈由 Agent 自动提交，不用再打开网页，适合经常反馈的用户。需要 GitHub 账号。安装时 Windows 可能弹出管理员确认。授权后 gh 能读写本账号的仓库（GitHub 规定的最低权限），令牌存在系统凭据管理器中，可随时用 `gh auth logout` 撤销。

9. 按回答处理：
   - 反馈：去掉 `--dry-run` 运行，脚本自动选 gh 或浏览器。
   - 安装 gh 后反馈、登录 gh 后反馈：先告诉用户接下来的操作：在管理员确认框点“是”（已安装时没有这步）；在打开的授权页粘贴剪贴板里的验证码；点 Authorize。再把 `--dry-run` 换成 `--setup-gh` 运行，命令超时设为 10 分钟。安装或登录失败时，脚本本次改用浏览器。退出码为 3 时没有 winget，脚本已打开 gh 下载页；请用户安装后回复，再运行同一命令。用户不装时，改用 `--method browser`。
   - 用浏览器反馈：加 `--method browser` 运行。
   - 用邮件反馈：加 `--method email` 运行，告诉用户收件邮箱、邮件主题和附件路径。
   - 不反馈：保留文件，结束。
   - 有安装或登录 gh 的选项，而用户选了浏览器或邮件反馈时，在 `okwwcharcode.local.md` 记一行 `gh 引导：不再推荐`。

## 输出与通过条件

- 提议文件通过 `submit_proposal.py` 的格式和隐私检查。
- 每条提议有类型、位置、原文、提议、背景、证据、运行条件和验证状态。
- 用户只被问一次，且回答前没有提交任何内容。
- 反馈后告诉用户 Issue 链接，或页面已打开待提交，或邮件发送信息。
- 安装或登录 gh 前，用户已在题干中看到权限、令牌位置和撤销方法。
- 未经维护者审核的提议不得写入语义卡。

需要补证据时，退回 [实测迭代](../iteration/SKILL.md)。

进入、退回或交给其他阶段时，按 [总入口的阶段切换](../../SKILL.md#阶段切换) 加载。
